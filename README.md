# بقالة الحي

متجر بقالة عربي متجاوب مع مساحة منفصلة للزبائن (`/` و`/auth`) ولوحة إدارة (`/admin`). يعتمد الخادم على Python القياسي وSQLite، ولا يحتاج إلى تثبيت حزم لتشغيله محلياً.

## التشغيل المحلي

1. ثبّت Python 3.10 أو أحدث.
2. عيّن كلمة مرور إدارة جديدة في الطرفية، ثم شغّل الخادم:

```sh
STORE_ADMIN_PASSWORD='choose-a-long-unique-password' python3 server.py
```

3. افتح `http://127.0.0.1:8000` للزبائن، أو `http://127.0.0.1:8000/admin` للإدارة. اسم المستخدم الافتراضي `admin` ويمكن تغييره عبر `ADMIN_USERNAME`.

تُحفظ الحسابات والمنتجات والطلبات والجلسات في `data/store.sqlite3`، وتُحفظ صور المنتجات في `data/uploads`. كل المتصفحات ترى البيانات نفسها عبر الخادم. تبقى البيانات بعد إعادة التشغيل ما دام مجلد التخزين موجوداً؛ عند النشر استخدم قرصاً دائماً واضبط `APP_DATA_DIR` عليه، وخذ نسخاً احتياطية دورية. لا تضع كلمة المرور أو مفتاح الذكاء الاصطناعي في ملفات الواجهة أو Git.

## الوظائف

- حساب زبون مستقل بالبريد والجوال وكلمة المرور، مع تسجيل الدخول بالبريد أو الجوال.
- متجر ببحث وتصنيفات وسلة وعنوان قابل للإدخال وموقع GPS اختياري، مع احتساب الإجمالي والتحقق من المخزون في الخادم.
- لوحة إدارة مستقلة لإضافة المنتجات وتعديل السعر والمخزون والصورة والتوفر، وحذفها بعد تأكيد داخل الموقع.
- إعداد اسم المتجر ورقم واتساب ومتابعة الطلبات وحالاتها؛ تتزامن الواجهات المفتوحة كل 30 ثانية وعند العودة إلى التبويب.
- عند إتمام الطلب يُحفظ أولاً، ثم يفتح واتساب برسالة جاهزة إلى رقم المتجر؛ على الزبون ضغط إرسال داخل واتساب.
- مساعد تسوق يرشح منتجات الكتالوج محلياً دون مفتاح. لإجابات الذكاء الاصطناعي، اضبط `AI_API_KEY` اختيارياً في بيئة الخادم.
- الواجهة باللغتين العربية والإنجليزية، وتدعم الهاتف وسطح المكتب.

## التشغيل على شبكة محلية

يستمع الخادم المحلي إلى الشبكة افتراضياً؛ افتحه من الأجهزة الأخرى باستخدام عنوان IP لهذا الجهاز مع المنفذ `8000`. هذا لا ينشر التطبيق على الإنترنت.

هذا المشروع لا يتضمن بوابة دفع إلكتروني أو إرسال واتساب آلياً. روابط `wa.me` تفتح رسالة معدّة ولا ترسلها دون تأكيد المستخدم. قبل استقبال العملاء فعلياً، أضف حماية من محاولات الدخول المتكررة، نسخاً احتياطية دورية، مراقبة للخادم، وسياسة خصوصية وشروط استخدام مناسبة.

## نشر دائم على Vercel

يتحول التطبيق في Vercel إلى Flask Function. قاعدة PostgreSQL وصور المنتجات خارج وظيفة Vercel كي تبقى دائمة بين الطلبات والنشر.

1. أنشئ مشروع Supabase، وشغّل محتوى `supabase-schema.sql` في SQL Editor.
2. في إعدادات Supabase، اختر اتصال Transaction Pooler وانسخ `DATABASE_URL`، وأنشئ مفتاح خدمة `service_role`. المفتاح سري ولا يوضع في Git أو المتصفح.
3. أنشئ مستودع GitHub خاصًا وارفع ملفات المشروع. اربط المستودع بمشروع Vercel.
4. أضف متغيرات البيئة التالية في إعدادات Vercel Production: `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_STORAGE_BUCKET=product-images`, `ADMIN_USERNAME`, `STORE_ADMIN_PASSWORD`, `HTTPS=true`. أضف `AI_API_KEY` فقط إذا أردت إجابات الذكاء الاصطناعي.
5. قبل استقبال العملاء، غيّر `STORE_ADMIN_PASSWORD` إلى سر جديد قوي من لوحة Vercel، ثم أعد النشر.
6. لنقل البيانات المحلية الحالية، ثبّت اعتماديات المشروع مرة واحدة عبر `python3 -m pip install -e .`، ثم شغّل `python3 migrate_to_supabase.py` من مجلد المشروع وأدخل القيم المطلوبة مباشرة في الطرفية. ينقل المستخدمين والطلبات والمنتجات والإعدادات والصور، ولا ينقل جلسات الدخول؛ سيحتاج الجميع لتسجيل الدخول مجدداً. قاعدة البيانات المحلية تُقرأ فقط.

الخطة والحدود والفوترة تعتمد على حسابات Vercel وSupabase. لم يتم إنشاء الخدمات أو قبول رسومها؛ أكمل ربط الحسابات وراجع تكلفتها في لوحات المزوّدين قبل النشر.
